# ساختار مخزن (`--structure`)

وضعیت: **R14-A1 پیاده‌سازی شده است**: ماژول‌ها، importها، طبقه‌بندی importها و
چرخه‌ها. نمادها و فراخوانی‌ها، entry pointها و شناسه‌ی ساختاری پایدار **هنوز
پیاده‌سازی نشده‌اند** (R14-A2 و R14-A3، به `docs/R14A_PLAN.md` نگاه کنید).

`sarand --structure` سورس پایتون پروژه را با ماژول استاندارد `ast` می‌خواند و ساختار
را به گزارش اضافه می‌کند. هرگز کد مخزن را اجرا نمی‌کند و فقط فایل‌هایی را می‌خواند که
گزارش اجازه‌ی خواندنشان را دارد (نه فایل علامت‌خورده به‌عنوان راز، نه فایل بزرگ‌تر از
حد اندازه؛ چنین فایلی با `skipped_size` فهرست می‌شود، نه حذف). به‌طور پیش‌فرض خاموش
است و گزارش پیش‌فرض تغییر نمی‌کند.

## چهار چیزی که جدا می‌مانند

| چیز | از کجا می‌آید | سرند با آن چه می‌کند |
|---|---|---|
| وابستگی **اعلام‌شده** | `pyproject.toml`، `requirements.txt` | به‌عنوان شاهد روی بسته‌ی بیرونی ثبت می‌شود؛ خودش هرگز import نیست |
| بسته‌ی **نصب‌شده** | محیط | هرگز خوانده نمی‌شود |
| import **یافت‌شده در سورس** | دستور `import` و فراخوانی `importlib`/`__import__` | یک یال |
| رابطه‌ی **حل‌شده‌ی** مخزن | یالی که هدفش ماژول مخزن است | گراف import و چرخه‌ها |

## import به چه چیزی حل می‌شود (`target_class`)

| کلاس | معنا |
|---|---|
| `internal` | یک ماژول همین مخزن (یا بسته‌ی namespace ضمنی) |
| `stdlib` | نام کتابخانه‌ی استاندارد؛ فهرست همان `sys.stdlib_module_names` مفسری است که سرند را اجرا کرده و در `meta` ثبت می‌شود |
| `external_declared` | ماژول مخزن نیست و نام نرمال‌شده‌اش با یک وابستگی اعلام‌شده برابر است |
| `external_unmatched` | ماژول مخزن نیست، stdlib نیست، و اعلانی ندارد. نام import با نام توزیع می‌تواند فرق کند (`yaml` و `pyyaml`) و سرند metadata نصب‌شده را نمی‌خواند، پس حدس نمی‌زند؛ این همان فهرست «بیرونیِ حل‌نشده» است |
| `internal_unresolved` | نام از یک بسته‌ی مخزن شروع می‌شود ولی هدفی پیدا نشد: زیرماژول گم‌شده، نام مبهم (چند ماژول جور است)، import نسبی فراتر از بسته‌ی بالا |
| `dynamic` | نام ماژول در زمان اجرا محاسبه می‌شود (`importlib.import_module(name)`) |

## اعتماد (confidence)

فقط با این قواعد داده می‌شود. شرطی‌بودن import یک **پرچم** است، نه سطح اعتماد.

| سطح | قاعده | مثال‌ها |
|---|---|---|
| `definite` | نام با قواعد خود پایتون دقیقاً به یک ماژول مخزن (یا نام stdlib یا اعلام‌شده) متصل می‌شود | `import a.b` وقتی `a/b.py` هست؛ import نسبی که روی یک فایل می‌نشیند؛ نام stdlib؛ نامی برابر با یک اعلان |
| `probable` | یک نامزد هست ولی یک فرض لازم بود | همان نام ماژول در دو ریشه هست و ریشه‌ی خود import‌کننده ترجیح داده شد؛ ماژول مخزن نام stdlib را سایه می‌زند؛ `importlib.import_module("literal")`؛ بسته‌ی بیرونی که فقط با حذف مطابقت یافته |
| `unknown` | شاهد نمی‌تواند هدف را نام ببرد | نام ماژول محاسبه‌شده؛ نام مبهم؛ زیرماژول گم‌شده؛ import نسبی بدون بسته‌ی والد |

یال `unknown` هرگز وابستگی نیست: هرگز چرخه نمی‌سازد.

## پرچم‌های import

`conditional`، `type_only`، `lazy`، `relative`، `star`.

- **`conditional`**: وقتی scope اجرا می‌شود ممکن است این import اجرا نشود. برای شاخه‌های
  `if`/`elif`/`else`؛ بدنه‌ی `try` ای که handler ی `ImportError` از آن محافظت می‌کند؛ هر handler ی
  `except`؛ `else` ی `try`؛ بدنه و `else` ی `for` و `while`؛ caseهای `match`؛ سمت راست
  `and`/`or`؛ شاخه‌های عبارت شرطی؛ بدنه‌ی comprehension تنظیم می‌شود. برای `finally` یا `with`
  **تنظیم نمی‌شود** (context manager می‌تواند exception را ببلعد، ولی سرند آن را تعیین
  نمی‌کند). `try` بدون handler ی `ImportError` بدنه‌اش را شرطی نمی‌کند.
- **`type_only`**: زیر `if TYPE_CHECKING:` (و `else` ی `if not TYPE_CHECKING:`)؛ همیشه
  `conditional` هم هست.
- **`lazy`**: داخل بدنه‌ی تابع یا lambda، یعنی import هنگام فراخوانی تابع اجرا می‌شود.
  دکوراتور، مقدار پیش‌فرض و annotation هنگام تعریف اجرا می‌شوند، پس lazy نیستند.
- **`relative`**: شکل `from . import x`. **`star`**: `from m import *`.

یک handler از import **محافظت می‌کند** وقتی `ImportError`، `ModuleNotFoundError`، `Exception` یا
`BaseException` را نام ببرد (یا اصلاً نوع نداشته باشد)، به‌صورت نام متصل به builtin، یا
`builtins.<name>`، یا alias ای که از builtin گرفته شده (`IE = ImportError`)، یا داخل tuple
از این‌ها. `foo.ImportError` و `ImportError` ی که دوباره مقدار گرفته حساب نمی‌شوند.

## شکل‌های شناخته‌شده و حدشان

نام‌ها **بر اساس scope** حل می‌شوند، نه بر اساس املا. جدول انقیاد فقط `TYPE_CHECKING`،
ماژول‌های `typing`/`typing_extensions`، `importlib` و `builtins` (زیر هر alias)،
`importlib.import_module`، `importlib.__import__`، `__import__` و خانواده‌ی `ImportError` را
می‌شناسد. نامی که به چیز دیگری دوباره متصل شود، یا در یک scope به دو شکل متفاوت متصل باشد،
مبهم است و شناخته نمی‌شود. پشتیبانی‌شده:

- sentinel ی `TYPE_CHECKING` به شکل `from typing import TYPE_CHECKING [as T]`،
  `typing.TYPE_CHECKING` (همچنین با `import typing as t`) و ترفند `TYPE_CHECKING = False`.
  نامی با همین املا که از جای دیگر بیاید (`from .compat import TYPE_CHECKING`،
  `custom.TYPE_CHECKING`، پارامتر، متغیر) فقط `conditional` است.
- `importlib.import_module(name, package=None)` و `__import__(name, globals, locals, fromlist,
  level)` ی builtin، با نام خودشان یا با alias (`import importlib as il`،
  `from importlib import import_module as im`، `from builtins import __import__ as ci`). نام
  literal مثل import حل می‌شود ولی حداکثر `probable` است. نام نسبی در `import_module` نسبت
  به آرگومان `package=` حل می‌شود (مثل `importlib.util.resolve_name`)؛ level ی `__import__` فقط
  وقتی نسبت به ماژول import‌کننده حل می‌شود که `globals` همان فراخوانی ساده‌ی `globals()` باشد.
  `fromlist` دنبال نمی‌شود.
- نام محاسبه‌شده، فراخوانی با `*args` یا `**kwargs`، یا `package=` ی محاسبه‌شده `dynamic`
  (unknown) است.
- `exec` و `eval` (فقط وقتی همان builtin باشند) فایل را با `dynamic_construct_seen` علامت
  می‌زنند؛ مکانشان **ثبت نمی‌شود** (برایشان یالی وجود ندارد).

پشتیبانی نشده (ساختار اصلاً دیده نمی‌شود): assignment expression (`:=`) و نام‌هایی که
`from m import *` می‌آورد به‌عنوان انقیاد؛ alias ی alias؛ `getattr(importlib, "import_module")`؛
`__import__` ی رسیده از `globals()["__import__"]`؛ کد `eval` شده. جدول آگاه از scope ترتیب جست‌وجوی
پایتون را دنبال می‌کند (scope ی class داخل تابع تودرتو رد می‌شود) و نامی که در جایی `global`
اعلام شده در سطح ماژول مبهم است.

## ریشه‌های سورس و نام ماژول

نام ماژول از یک ریشه‌ی سورس شروع می‌شود. ریشه‌ی یک فایل به ترتیب این است:

1. ریشه‌ی اعلام‌شده در `pyproject.toml` که فایل را در بر بگیرد: maturin `python-source`؛
   setuptools `package-dir` (کلید خالی `{"" = "src"}` یعنی بدون پیشوند؛ کلید نام‌دار
   `{"mypkg" = "lib/other"}` می‌گوید پوشه‌ی `lib/other` **همان** بسته‌ی `mypkg` است، پس
   `lib/other/a.py` همان `mypkg.a` است)؛ setuptools `packages.find.where`. بلندترین پوشه‌ی
   اعلام‌شده برنده است؛
2. وگرنه نزدیک‌ترین پوشه‌ی بالادست بدون `__init__.py`.

ریشه‌ی اعلام‌شده باید مسیر نسبی داخل مخزن باشد: مسیر مطلق، backslash، درایو ویندوز، یا `..` ی
که از مخزن بیرون برود **رد** و در `meta.rejected_roots` فهرست می‌شود (هرگز بی‌صدا استفاده یا
حذف نمی‌شود)؛ `./src/` و `a/../b` نرمال می‌شوند.

نام ماژول فقط برای مسیری داخل ریشه‌اش ساخته می‌شود. `__init__.py` ی سطح ریشه نام قابل‌import
ندارد (با ماژول خالی فهرست می‌شود و importهایش با مسیر فایل گزارش می‌شود). پوشه‌ی بدون
`__init__.py` بسته‌ی **namespace** ضمنی است؛ بسته‌ی namespace می‌تواند در چند ریشه سهم داشته
باشد (PEP 420) و برای هر (نام، ریشه) یک `ModuleEntity` نگه داشته می‌شود؛ نامی که در هر ریشه
بسته‌ی عادی است همزمان namespace هم نیست. نامی که در دو ریشه هست فقط وقتی حل می‌شود که
ریشه‌ی خود import‌کننده دقیقاً یکی از آن‌ها را داشته باشد (`probable`)؛ وگرنه
`internal_unresolved` است.

راه‌اندازی بسته‌ی والد (`import a.b.c` ابتدا `a/__init__.py` را اجرا می‌کند) به‌عنوان یال
**مدل نمی‌شود**: هر بسته و زیرماژول‌هایش را چرخه می‌کرد. `from pkg import name` فقط وقتی به
`pkg` وابسته است که `name` زیرماژول مخزن نباشد.

**مسیرهای داده‌شده به builder** (`included`، `skipped`) نسبی و داخل پروژه و بدون `..` هستند؛
مسیر مطلق یا خروج با parent باعث `ValueError` می‌شود.

## چرخه‌ها

مؤلفه‌های قویاً همبند گراف import مخزن، بدون بازگشت، به‌اضافه‌ی ماژولی که خودش را
import می‌کند. فقط یال‌هایی حساب می‌شوند که به ماژول مخزن با اعتماد `definite` یا
`probable` حل شده باشند.

`Cycle.edges` **همه‌ی** چنین یال‌هایی است که دو سرشان در چرخه است، از جمله یال‌های lazy و
type-only، هرکدام با پرچم خودش. مجموعه‌ی کمینه‌ی یال‌هایی که یک حلقه را می‌بندند نیست. چرخه
**eager** است وقتی پس از حذف یال‌های `type_only` و `lazy` هنوز بماند، یعنی بتواند هنگام import
شکست بخورد؛ یال‌های `conditional` هنوز eager حساب می‌شوند (روی بعضی مسیرها اجرا می‌شوند).
وگرنه «lazy or type-only» فهرست می‌شود.

## قرارداد مدل

- **دو نسخه‌ی شما.** شمای **گزارش** بیرونی (`schema_version`، `"1.7"`) همراه گزارش JSON نسخه
  می‌شود (`docs/JSON_SCHEMA.fa.md`). شمای **مدل ساختار** همان `structure.schema` است، یک عدد
  صحیح، امروز `1`. این دو مستقل تغییر می‌کنند.
- **مختصات.** `line` از ۱ شروع می‌شود (۰ = نامعلوم). `col` و `end_col` **offset بایتی UTF-8**
  از ۰ در همان خط‌اند، دقیقاً همان‌طور که `ast` می‌دهد (`end_col` برابر ۰ = نامعلوم).
  `SyntaxError` کاراکتر گزارش می‌کند؛ سرند آن را به بایت تبدیل می‌کند تا کل مدل یک واحد داشته
  باشد. form feed شماره‌ی خط را جابه‌جا نمی‌کند (خط با `\n`، `\r\n` یا `\r` تمام می‌شود، مثل
  tokenizer پایتون).
- **اعتبارسنجی.** هر موجودیت هنگام ساخته‌شدن فیلدهایش را بررسی می‌کند: مقداری بیرون از
  واژگان بسته، مسیر نادرست (مطلق، backslash، `..`) یا مختصات منفی `ModelError` می‌دهد که نام
  فیلد و مقدارهای مجاز را می‌گوید. پس داده‌ی نامعتبر به خلاصه یا رندر نمی‌رسد.
- **تغییرناپذیری.** عمیق: mappingهای تودرتو فقط‌خواندنی‌اند و دنباله‌ها tuple؛ ساختن
  موجودیت چیزی را که می‌گیرد کپی می‌کند.
- **نامعلوم نامعلوم می‌ماند.** فایلی که خوانده نشد `size: null`، `sha256` خالی و محدودیت
  `unreadable` دارد؛ هرگز مثل فایل خالی نشان داده نمی‌شود.
- **شاهد** متن خود دستور است، از ستون شروع تا ستون پایانش (کامنت انتهایی جزو آن نیست)،
  خط‌هایش با فاصله‌ی تکی چسبیده و در ۲۴۰ کاراکتر بریده می‌شود (برش با `...` تمام می‌شود).
  `note` متن خود سرند برای توضیح یال حل‌نشده یا پویا است؛ هرگز متن سورس نیست.
- **خروجی کانونی.** serializer هر مجموعه را با کلید صریح مرتب می‌کند (فایل‌ها با مسیر؛
  ماژول‌ها با نام، ریشه، مسیر؛ بیرونی‌ها با نام؛ یال‌ها با مبدأ، مکان، نام درخواستی و بقیه؛
  چرخه‌ها با ماژول‌هایشان؛ یال‌های چرخه مثل یال‌ها)، mappingها را بازگشتی با کلید مرتب
  می‌کند و دنباله‌های `meta` را مرتب می‌کند. دنباله‌های داخل `extensions` ی فایل ترتیبشان
  را نگه می‌دارند. پس دو مدل برابر، با هر ترتیبی که سازنده‌ها داشتند، همان بایت‌ها را
  می‌دهند و serialize کردن مدل را تغییر نمی‌دهد.

## منشأ تجزیه و محدودیت‌ها

هر فایل منشأ دارد: parser (`python-ast`)، نسخه‌ی مفسر، کامل‌بودن (`full`، `partial`،
`failed`، `skipped_size`) و کدهای محدودیت: `syntax_error`، `encoding_error`، `recursion_limit`،
`resource_limit`، `node_cap`، `too_large`، `unreadable`، `dynamic_construct_seen`؛
`unsupported_syntax_for_interpreter` تعریف شده ولی **تولید نمی‌شود**: خطای نحوی را نمی‌شود
به‌طور قابل‌اعتماد به دستور زبان جدیدتر نسبت داد، پس فقط `syntax_error` گزارش می‌شود. فایلی
که خوانده نشود با دلیل و مکان خطا در خروجی می‌ماند، پس فایل خراب هرگز صفر بی‌صدا نیست.

محافظ‌ها: شکست بازگشت هنگام پیمایش فقط همان دستور را از دست می‌دهد (فایل `partial` است و
بقیه‌ی importها می‌مانند)؛ سقف گره (۱٬۰۰۰٬۰۰۰) و شکست حافظه پیمایش را متوقف می‌کنند
(`partial`، با آنچه پیش از آن پیدا شده)؛ شکست بازگشت یا حافظه هنگام parse فایل را `failed`
می‌کند. فقط همین شکست‌ها مدیریت می‌شوند؛ هر چیز دیگر باگ است و بلعیده نمی‌شود.

**«شناسایی نشد» یعنی «وجود ندارد» نیست.** importهای پویا، `getattr`/`setattr`،
monkey-patching، بارگذاری پلاگین با entry-point و کد تولیدشده می‌توانند رابطه‌هایی بسازند
که خواندن ایستا نمی‌بیند. `dynamic_construct_seen` یعنی فایل چنین ساختاری دارد.

دو ورودی محیطی در `meta` نام برده می‌شوند و پنهان نیستند: نسخه‌ی مفسر (دستور زبان `ast`
و فهرست stdlib به آن بستگی دارند، پس فایل با نحو جدیدتر روی مفسر قدیمی‌تر `failed` است) و
منبع فهرست stdlib.

## کجا دیده می‌شود

- **JSON** (`structure`، شمای بیرونی ۱٫۷): همه‌چیز، از جمله هر یال با شاهد، note و مکانش. به
  `docs/JSON_SCHEMA.fa.md` نگاه کنید.
- **Markdown و HTML**: شمارش‌ها؛ چرخه‌های import (۱۰ مورد اول)؛ **importهای حل‌نشده و پویا**
  (۲۰ مورد اول): importهایی که کلاس هدفشان `internal_unresolved` یا `dynamic` است، با دلیل؛
  و **بسته‌های بیرونی import‌شده** (۳۰ مورد اول، از نوع `external_declared` و
  `external_unmatched`، با اینکه چند ماژول هرکدام را import می‌کنند). جمع کل همیشه نشان داده
  می‌شود و فهرست بریده می‌گوید چند مورد نشان داده نشده. بخش خالی رسم نمی‌شود. هر سلول
  escape می‌شود (موجودیت HTML در HTML؛ pipe و شکست خط در جدول Markdown).
- **Text**: یک خط.
- **SARIF**: شامل نمی‌شود.

همه‌ی شمارش‌ها از یک جا می‌آیند (`structure/serialize.py` و `core/report_views.py`)، پس
قالب‌ها هم‌نظرند.

## هنوز پیاده‌سازی نشده

نمادها، فراخوانی‌ها، وراثت، ارجاع‌ها و entry pointها (R14-A2)؛ شناسه‌ی ساختاری پایدار و
fingerprint، ارزیابی روی مخزن واقعی و گیت مرحله (R14-A3). زبان‌های دیگر شروع نشده‌اند. ساختارهای
import پایتون که هنوز پشتیبانی نمی‌شوند زیر «شکل‌های شناخته‌شده و حدشان» فهرست شده‌اند.
